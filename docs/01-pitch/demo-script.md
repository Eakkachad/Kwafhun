# สคริปต์นำเสนอ & Q&A Defense Script

> สำหรับ Presenter ฝึกตอบคำถามกรรมการ เนื้อหานี้จัดเรียงตาม Overclaim ที่วิเคราะห์ไว้ใน `docs/03-architecture/risk-defense.md`

## สคริปต์พูดเปิด (Elevator Pitch ~60 วินาที)

> "ทุกคาบแนะแนว เด็กราว 1.8 ล้านคนในครัวเรือนยากจน ถูกสอนให้ฝันในกรอบแคบๆ เพราะไม่เห็น Role Model ที่หลากหลาย พออายุ 6–8 ปี พวกเขาก็ตัดอาชีพทักษะสูงออกจากชีวิตไปแล้ว 'คว้าฝัน' คือ Netflix of Dreams เปลี่ยนคาบแนะแนว 1 ชั่วโมง/สัปดาห์ ให้เป็นพื้นที่ค้นหาความฝัน AI สร้างแผนส่วนบุคคล และ Router เชื่อมเด็กเข้าหาทุน กสศ. ที่มีอยู่แล้วแต่เข้าไม่ถึง — เราทำงานร่วมกับ AIS 5G, LearnDi และ Cloud เพื่อส่งสิ่งนี้ถึงห้องเรียนแบบ Offline-Ready ครับ"

## Q&A Defense — คำถามกรรมการ + บทตอบ

### Q1: "ถ้าโรงเรียนไม่มีอินเทอร์เน็ตเลย จะใช้อย่างไร?"

> "ระบบเราใช้ PWA Offline Caching ครูดาวน์โหลดเนื้อหาคาบเรียนสัปดาห์นั้นผ่านสัญญาณ AIS 5G บนโทรศัพท์ครูไว้ล่วงหน้าก่อนเข้าห้องเรียน พออยู่ในห้องก็เปิดบนโปรเจกเตอร์ได้ทันทีโดยไม่ต้องพึ่งเน็ตสดครับ ไม่ต้องซื้อฮาร์ดแวร์ใหม่"

### Q2: "เด็กยากจนมาก ต่อให้มีความฝันก็ไม่มีเงินเรียนต่อ โครงการนี้แก้อย่างไร?"

> "ระบบเราไม่ได้จบแค่การแนะแนวครับ เรามี Opportunity Pipeline ดึงข้อมูลทุน กสศ. (เช่น ทุนนวัตกรรมสายอาชีพชั้นสูง) และทุนมหาวิทยาลัยมาแมตช์กับเด็กตั้งแต่ ม.ต้น ทำให้เด็กรู้ว่าถ้าตั้งใจเรียนวิชานี้และสร้าง Portfolio ตามนี้ มีทุนเรียนฟรี 100% รองรับอยู่ ไม่ใช่ฝันที่ไร้ทางไปครับ"

### Q3: "ครูแนะแนวงานเยอะอยู่แล้ว ครูจะยอมใช้ระบบนี้ได้อย่างไร?"

> "ออกแบบแบบ Zero-Setup ครับ ครูไม่ต้องกรอกข้อมูลเด็กแม้แต่คนเดียว แค่เปิดเว็บหน้าจอห้องเรียน ให้เด็กทำกิจกรรมร่วมกันผ่าน QR Code ระบบประมวลผลสรุปเป็นไฟล์ 'รายงานวิเคราะห์ความสนใจนักเรียน' ให้อัตโนมัติ ครูเอาไปยื่นประเมิน สพฐ. ได้ทันที — ระบบไม่ใช่ภาระเพิ่ม แต่คือเครื่องมือทุ่นแรงครับ"

### Q4: "ข้อมูลเด็กที่เป็นผู้เยาว์ กฎหมาย PDPA ดูแลอย่างไร?"

> "เราแยกข้อมูลเป็น 2 ชั้นครับ ชั้นวิเคราะห์ (AI Roadmap/วัดความสนใจ) ใช้รหัสจำลอง ไม่มีชื่อจริงหรือเลขบัตรประชาชน ส่วนชั้นรายงานที่ครูจะยื่น สพฐ. ต้องใช้ตัวตนจริง ซึ่งตาม PDPA มาตรา 20 เด็กอายุเกิน 10 ปี — คือกลุ่มเป้าหมายของเราเกือบทั้งหมด — ต้องได้รับความยินยอมจากทั้งตัวเด็กเองและผู้ปกครองร่วมกัน เราจะขอ Consent สองฝ่ายนี้ล่วงหน้าผ่านโรงเรียนก่อนเก็บเสมอ — ระบบค่าเริ่มต้นคือ Anonymous ยกเว้นจำเป็นจริงๆ และมีนโยบายคุ้มครองเด็กสำหรับพี่เลี้ยงด้วยครับ"

### Q5: "ถ้าอาชีพในคลังวิดีโอไม่ทันสมัย / ใครผลิตคอนเทนต์?"

> "เราไม่ได้ถ่ายทำเองทั้งหมดครับ ใช้ Crowdsourced Role Model Network — รวบรวมวิดีโอสั้นจาก Content Creator, นิสิตทุน กสศ., และ Alumni **ที่ได้รับอนุญาตให้ใช้** แล้วใช้ AI ทำ Content Tagging และซ้อน Interactive Quiz แทนการผลิตใหม่ทั้งหมด ทำให้อัปเดตได้ตลอดเวลาด้วยต้นทุนต่ำ และมีระบบคัดกรองคอนเทนต์เพื่อความปลอดภัยของเด็ก"

### Q6: "AI แนะนำคอร์สเรียนผิด/เลื่อนลอยได้หรือไม่?"

> "เราไม่ได้พึ่ง LLM แบบ open ครับ เราใช้ Constraint-Aware Matching Engine — ก่อนแนะนำระบบจะตัดตัวเลือกที่ 'เป็นไปไม่ได้' ออกก่อน (เช่น เกณฑ์ชั้นเรียน เกณฑ์ทุน พื้นที่) แล้วเหลือเฉพาะชุดที่ทำได้จริงจึงจัดลำดับ ข้อมูลทุกชุดป้อนและได้รับอนุญาตจากเราเอง (หลักสูตร สพฐ., ทุน กสศ., TCAS, AIS LearnDi) และผลลัพธ์ deterministic ตรวจสอบย้อนหลังได้ ทุกคำแนะนำ trace กลับไปที่มาข้อมูลได้ — ตอบกัน hallucination ด้วยสถาปัตยกรรม ไม่ใช่แค่คำสัญญาครับ"

### Q12b: "โมเดลต้องใช้ Cloud/GPU แรงๆ ไหม หรืออัปเดตข้อมูลยากไหม?"

> "สถาปัตยกรรมเราเป็น constraint-based + data lookup ครับ ตัว engine เบา ประมวลผลที่ Edge/Local ได้จริง เหมาะกับ AIS 5G/Cloud และเมื่อมีทุนหรือคอร์สใหม่ แค่เพิ่มข้อมูลเข้าไป ระบบก็แมตช์ได้ทันที ไม่ต้อง retrain เหมือน LLM — ทำให้อัปเดตได้ตลอดเวลาด้วยต้นทุนต่ำ"

### Q7: "รายได้ของแพลตฟอร์มมาจากไหน ใครจ่าย?"

> "โมเดล B2B2G ครับ ภาครัฐ/กสศ. สนับสนุนงบพัฒนาทุนมนุษย์ มหาวิทยาลัยจ่าย Sponsor/Matchmaking เพื่อดึงเด็กเข้าค่าย Open House และ AIS ได้ประโยชน์ด้าน ESG + ขยายฐานใช้ 5G/LearnDi — หลายฝ่ายได้ผลประโยชน์ร่วมกัน ไม่ใช่แค่ CSR"

### Q8: "ทำไมเริ่มจากเมืองหัวเมือง ไม่เริ่มจากชนบทที่ยากจนที่สุด?"

> "เพราะเรายึดหลัก 'พิสูจน์ให้ได้ก่อน' ครับ — เมืองหัวเมืองอย่าง ชลบุรี/ขอนแก่น/เชียงใหม่ มีมหาวิทยาลัยและทรัพยากรบุคคลรองรับอยู่แล้ว (ตามโมเดล Area-Based Career Coach ของ กสศ. ที่เริ่มจาก ชลบุรี เชียงใหม่ เช่นกัน) ในโรงเรียนหัวเมืองก็มีเด็กที่ยังไม่รู้ทางไปจริง เราจัดกิจกรรม 'ได้รู้-ได้ลอง-ได้ทำจริง' ใช้ทรัพยากรที่มีอยู่ งบต่อหัวต่ำ พอพิสูจน์ว่าโมเดลใช้ได้จริง ค่อยขยายสู่ชนบทผ่านเครือข่าย สพฐ. และ กสศ. — เริ่มจากที่ทำได้จริง แล้วเดินทางไปสู่คนที่ต้องการที่สุดครับ"

### Q9: "Gamification/ของรางวัล จะทำให้เด็กเสพติดหรือทำลายแรงจูงใจจริงหรือไม่?"

> "เราใช้หลักฐานทางวิชาการออกแบบครับ งานวิจัย Deci & Ryan 1999 พบว่าของรางวัลจับต้องได้รายกิจกรรมทำลายแรงจูงใจภายใน เราเลยไม่ทำแบบนั้น — Reward ของเราเป็น 'โอกาสจริง' เช่น ที่นั่งค่าย บูทแคมป์ หรือเส้นทางทุน ที่ต่อยอดความฝันได้ และเน้น Badge + คำชม + ความคืบหน้าส่วนตัว แทนการแข่งอันดับ ซึ่งสอดคล้องกับหลักการ Self-Determination Theory"

### Q10: "งบแค่ไหนจะพอจ่ายค่าที่นั่ง Bootcamp 2–3 ที่นั่ง?"

> "กลไกเงินมีอยู่แล้วครับ บริษัทซื้อทุนผ่าน กสศ. ได้ (เช่น เซ็นทรัล 'สานฝันทำเพื่อน้อง' 2,500 บาท/ทุน, ซูเปอร์จิ๋ว 400 ทุน/4 ล้านบาท) และบริจาค กสศ. ลดหย่อนภาษี 2 เท่า ส่วน Bootcamp สายดิจิทัลราคาประมาณ 45,000 บาท/รุ่น (TechUp) — เราทำหน้าที่เป็น 'ชั้นแมตช์' ที่คัดเด็กผ่าน Achievement + ข้อมูลการเรียนจริง ให้สปอนเซอร์มั่นใจว่าเงินไปถึงเด็กที่ตั้งใจจริง เราไม่ใช่ผู้หาเงินรายเดียว แต่เป็นตัวกลางลดความเสี่ยงของสปอนเซอร์ครับ"

### Q11: "การที่ผู้ใหญ่/นิสิตแชตกับเด็กผ่าน LINE มีความเสี่ยงด้านความปลอดภัยอย่างไร?"

> "เราออกแบบระบบคุ้มครองเด็กเป็นหลักครับ พี่เลี้ยงทุกคนต้องผ่าน Vetting (ยืนยันตัวตน/ตรวจประวัติ) แชตทุกช่องถูก monitor และมีช่องทางรายงานเหตุการณ์ ทำงานตามนโยบายคุ้มครองเด็กของสถานศึกษา และต้องได้รับ Consent ผู้ปกครองก่อนจับคู่ — ความปลอดภัยของเด็กมาก่อนการเข้าถึงครับ"

### Q12: "ระบบคัดกรองเด็ก จะไม่ซ้ำรอยความเหลื่อมล้ำแบบระบบ Portfolio เหรอ? (เด็กที่มีทรัพยากรได้เปรียบกว่า)"

> "เราแก้ตรงนี้ด้วยการย้ายคอร์สคัดกรองเข้า**คาบเรียน**ครับ — ทุกคนเรียนเท่ากันในห้อง ครูเป็นผู้ดำเนินการผ่านหน้าจอห้องเรียน ไม่ใช่ให้ไปเรียนที่บ้าน ใครมีเน็ต/อุปกรณ์ก็ไม่ได้เปรียบ เพราะเราไม่ได้วัด 'ทรัพยากรที่บ้าน' แต่วัด 'ความสนใจที่เกิดขึ้นจากประสบการณ์เท่าเทียม' ในห้องครับ"

## หลักการตอบ

1. **ตอบตรงประเด็นก่อน 1 ประโยค** แล้วค่อยขยาย
2. ถ้าไม่มีตัวเลขรองรับ → ตอบในระดับ "ออกแบบให้..." ไม่ใช่ "ผลลัพธ์ 100% แน่นอน"
3. ทุกสถิติที่พูด → ชี้ source ได้ (กสศ., NESDC, TDRI, OECD)
4. ถ้าถามเรื่อง "วัดผลอย่างไร" → ดึงจากตาราง KPI ใน `docs/05-roadmap/roadmap.md`
