> **v2 — ความหนาแน่นเทียบเท่า True Innovation Launchpad deck จริง** (`/Users/admin/Project/trueinnovationlaunchpad/True Innovation.pdf` — ทีม True NMR, 8 หน้าที่ตรวจแล้ว) และ **TrueMoney "Crispy Chicken Network" Challenger deck** — แต่ละสไลด์อ้างอิงมี **6-10 บล็อกข้อมูลย่อย** ต่อหน้า (กล่องสถิติ, ย่อหน้าอธิบาย, quote pull-out, ตาราง, ไอคอน+label, source citation ย่อยใต้แต่ละกล่อง) ไม่ใช่แค่หัวข้อ+ภาพประกอบ 2-3 โซนแบบเดิม

## วิธีใช้

1. Generate **ทีละสไลด์** — อย่ารวมหลายสไลด์ใน prompt เดียว โมเดลจะสับสนเรื่อง layout/ตัวเลข
2. แปะ **Style Bible** ไว้ต้น prompt ทุกครั้ง เพื่อให้ทั้งชุดหน้าตาเป็นเอกสารเดียวกัน
3. Ratio **16:9** ทุกสไลด์
4. เพราะแต่ละสไลด์ตอนนี้มี **6-10 บล็อกข้อความ** — ถ้าโมเดลอัดข้อความแน่นจนอ่านไม่ออก ให้สั่งเพิ่มในพรอมต์ว่า **"ลดขนาดฟอนต์ของย่อหน้ารองลงเพื่อให้อ่านออก คงเฉพาะตัวเลข/หัวข้อใหญ่"** แทนการตัดเนื้อหาออก — เป้าหมายคือความแน่นแบบ business case ไม่ใช่ความว่างแบบโปสเตอร์
5. **ตัวเลข/หัวข้อสั้น** ปล่อยให้โมเดลเขียนได้เลย — **ย่อหน้ายาว/ตารางเต็มบรรทัด** มีความเสี่ยงสะกดผิด ถ้าไม่ชัดให้ generate โครง (สี/กล่อง/เส้นตาราง เว้นที่ว่างข้อความ) แล้วใส่ทับด้วย Figma/Canva/PPT
6. ทุก prompt ปิดท้ายด้วย negative constraints ชุดเดียวกัน — อย่าตัดออก
7. ก่อนส่งเข้าโมเดล เทียบ "ข้อมูล/ตัวเลขที่ต้องปรากฏ" กับ `data/stats/stats.th.json` และเอกสารต้นทางที่อ้างอิงในแต่ละสไลด์อีกครั้ง

## Style Bible (แปะไว้ต้นทุก prompt)

```
สไตล์ภาพ: สไลด์ Business Case Competition ระดับมืออาชีพ (เทียบเท่า McKinsey/BCG case-comp deck หรือ Corporate Innovation Launchpad Pitch) — แน่นด้วยข้อมูลจริงหลายบล็อกต่อหน้า ไม่ใช่โปสเตอร์การตลาดที่มีข้อความน้อย ไม่ใช่ AI-art แฟนตาซี

BRAND BAR: แถบด้านบนสุดหนา ~7-8% ของความสูงภาพ พื้นสีกรมท่าเข้ม (Navy #0060AA) เต็มความกว้าง — มุมซ้ายของแถบมีคำว่า "คว้าฝัน" ตัวหนาสีขาว (wordmark ข้อความ ไม่ใช่โลโก้) — มุมขวาของแถบเว้นกล่องสี่เหลี่ยมเล็กว่างเปล่าเขียนคำว่า "[AIS LOGO]" เป็น placeholder เท่านั้น (ห้ามวาดโลโก้ AIS จริงเพราะเรื่องลิขสิทธิ์)

LAYOUT GRAMMAR: ใต้ brand bar คือ eyebrow label เล็กตัวพิมพ์ใหญ่สีส้ม (หมวดหมู่สไลด์ เช่น "PROBLEM ANALYSIS", "MARKET SIZING") ตามด้วยหัวข้อสไลด์ตัวหนาสีดำ/กรมท่าเข้มขนาดใหญ่ (ชิดซ้าย) และประโยคสรุป (subtitle) สีเทาเข้ม 1 บรรทัดใต้หัวข้อ — เนื้อหาหลักแบ่งเป็น **หลายโซนย่อย (6-10 บล็อก)** ด้วยกล่องพื้นหลังสี/เส้นแบ่งบางๆ ชัดเจน แต่ละบล็อกมีหัวข้อย่อยตัวหนา + ย่อหน้าอธิบายสั้น 2-4 บรรทัด — ไม่ใช่ freeform composition ที่มีที่ว่างเยอะ — ตัวเลขสำคัญใช้ตัวหนามาก (bold, ขนาดใหญ่เด่นกว่าข้อความรอบข้าง 3-4 เท่า) — ทุกบล็อกสถิติมี citation เล็กจิ๋วกำกับใต้ตัวเลขของตัวเอง (เช่น "(กสศ.)", "(OECD PISA)")

PALETTE: กรมท่า #0060AA (โทนหลัก/น่าเชื่อถือ) + ส้มอบอุ่น #E8590C (accent/ไฮไลต์/ความหวัง) + เขียว #006E21 (บวก/สำเร็จ) + แดง #BA1A1A (ความเสี่ยง/ปัญหา) + พื้นหลังเทาอ่อน #F2F3FA สำหรับกล่องข้อมูลรอง — ห้ามใช้ gradient ม่วง-ชมพูแบบ AI ทั่วไป

ICONS: line icon เส้นเรียบสีเดียว (ไม่ใช่ 3D, ไม่ใช่ emoji เบลอ) สไตล์เดียวกับไอคอน Font Awesome/Material — ใช้แทนแนวคิด (คน, กราฟ, โล่ป้องกัน, เครือข่าย ฯลฯ)

FOOTER BAR: แถบบางสีเทาอ่อนล่างสุดของภาพ ข้อความเล็กชิดซ้าย "source: [รวมแหล่งอ้างอิงหลักของสไลด์นั้น คั่นด้วยจุลภาค]" และเลขหน้าเล็กมุมขวาล่าง

TYPOGRAPHY: sans-serif เรียบทันสมัย (แนว Inter/Noto Sans Thai) น้ำหนักตัวอักษรคอนทราสต์ชัดระหว่างหัวข้อ (หนามาก) กับเนื้อหา (ปกติ) — ย่อหน้ารองใช้ฟอนต์เล็กกว่าหัวข้อย่อยชัดเจนเพื่อสร้างลำดับชั้นการอ่าน (visual hierarchy) เหมือนเอกสารนักวิเคราะห์จริง

PHOTOGRAPHY (ถ้ามีคนในภาพ): เด็กนักเรียน/วัยรุ่นไทยต่างจังหวัดที่ดูสมจริง เป็นธรรมชาติ ไม่ใช่ stock photo ยิ้มปลอม แสงธรรมชาติอบอุ่น ถ่ายสไตล์ cinematic 35mm ชัดตื้น (shallow depth of field)

PHOTO vs ICON RULE (สำคัญ): ทุกจุดที่สื่อถึง "คน" "นักเรียน" หรือ "อาชีพ" ให้ใช้ **ภาพถ่ายสมจริงแบบ AI-generated photoreal** แทนไอคอนเส้นเสมอ — ห้ามใช้ไอคอนคนแทนคนจริง ห้ามใช้ไอคอนอาชีพ (หมวกแพทย์, หมวกวิศวกร ฯลฯ) แทนภาพคนทำอาชีพนั้นจริง — ไอคอนเส้นสงวนไว้เฉพาะแนวคิดนามธรรมที่ไม่ใช่คน (กราฟ, ลูกศร, โล่ป้องกัน, เมฆ, ฐานข้อมูล, จอมือถือ, เอกสาร) เท่านั้น เมื่อ prompt ของสไลด์ใดเขียนว่า "ไอคอนคน" หรือ "ไอคอนอาชีพ" ให้อ่านเป็น "ภาพถ่ายคน/อาชีพนั้นแบบสมจริง" แทนเสมอ

ASPECT: 16:9 (1920x1080)
Negative: ห้ามมีลายน้ำ, ห้ามใบหน้าคนบิดเบี้ยว, ห้ามใช้โลโก้ AIS/หน่วยงานจริง (ใช้ placeholder ข้อความแทนเสมอ), ห้ามตัวหนังสือที่อ่านไม่ออก/สะกดผิด (ถ้าไม่มั่นใจให้เว้นที่ว่างแทนการเดาตัวอักษร), ห้าม gradient ม่วง-ชมพูแบบ generic AI, **ห้ามพื้นที่ว่างเปล่าเกิน 15% ของสไลด์ — ต้องแน่นด้วยข้อมูลจริงแบบ business case competition เสมอ**
```

## Slide 0 — Cover

**Action Title:** คว้าฝัน (Catch the Dream) — Netflix of Jobs & Career Navigator for Thai Youth

**ข้อมูล/ตัวเลขที่ต้องปรากฏ:** ไม่มีสถิติ — แต่เพิ่มความหนาแน่นด้วย value-prop callouts 3 อัน + badge เดียว (ตามแบบ True Innovation หน้า 1 ที่มีไอคอน "Assessing risk", "5-Year Forecast", "Accurate Planning" + วงกลม badge "Blood test · One time" มุมล่างขวา)

**Layout:** แนวทแยง 60/40 เหมือนเดิม + เพิ่ม **แถบไอคอน value-prop 3 อันแนวตั้งมุมขวาบน** และ **วงกลม badge มุมล่างขวา**

**Prompt:**
```
[แปะ Style Bible]

ภาพปกสไลด์ (Cover) ของโครงการ "คว้าฝัน (Catch the Dream)"
Layout แบ่งแนวทแยงมุม 60/40:

ฝั่งซ้าย (60%): พื้นหลังไล่โทนกรมท่าเข้ม (#0060AA ไปเข้มขึ้น) มีลวดลายเส้น network/กราฟจางๆ เป็นพื้นผิว (สื่อ Knowledge Graph) — บนสุดมี pill badge ขอบขาวเล็ก "AIS JUMP THAILAND HACKATHON 2026 · FUTURE READY TALENT" — กลางภาพหัวข้อใหญ่มากตัวหนาสีขาว "คว้าฝัน" บรรทัดถัดไปสีส้ม #E8590C "Catch the Dream" — ใต้ลงมา tagline สีขาวอมเทา "Netflix of Jobs & Career Navigator for Thai Youth" — ใต้ tagline อีกบรรทัดเล็กกว่า สีขาวจาง "เปลี่ยนคาบแนะแนว 1 ชั่วโมง/สัปดาห์ ให้เป็นเส้นทางอาชีพที่จับต้องได้จริง"

ฝั่งขวา (40%): ภาพถ่ายสมจริงของเด็กนักเรียนไทยวัย 12-15 ปี (ครึ่งตัว มองจากด้านหลัง/ด้านข้าง) ยืนมองขอบฟ้ายามเย็นที่มี **ภาพถ่ายวงกลมเล็กจางๆ ลอยเป็นกลุ่ม 5-6 ภาพของคนจริงกำลังทำอาชีพต่างๆ** (นักบินอวกาศในชุดสูท, นักวิทยาศาสตร์ในแล็บ, สัตวแพทย์กับสัตว์, วิศวกร, ครีเอเตอร์ถือกล้อง) แทนไอคอนอาชีพ — แต่ละภาพวงกลมมีขอบบางสีขาวจาง เหมือนลอยอยู่ในความคิดของเด็ก แสงสีส้มทองจากขอบฟ้า

แถวไอคอน value-prop 3 อัน วางแนวตั้งซ้อนกันมุมขวาบนของภาพ ทับบนพื้นหลังจางๆ แต่ละอันมีวงกลมไอคอนเล็ก + ข้อความสั้น 2 บรรทัดสีขาว:
  ไอคอน 1 (เข็มทิศ): "Discover 30+ เส้นทางอาชีพ / ผ่านวิดีโอ Role Model จริง"
  ไอคอน 2 (เอกสาร): "Roadmap ส่วนบุคคล / จาก Constraint-Aware Engine"
  ไอคอน 3 (จับมือ): "เชื่อมทุน+ค่ายจริง / ผ่าน Opportunity Router"

วงกลม badge มุมล่างขวา ขอบสีส้มหนา พื้นขาว ตัวอักษรกรมท่า:
  บรรทัดบน (เล็ก): "คาบแนะแนว"
  บรรทัดกลาง (ใหญ่ตัวหนา): "1 ชม./สัปดาห์"
  บรรทัดล่าง (เล็ก): "ไม่ต้องเพิ่มภาระครู"

แถบขาวมุมล่างซ้ายทับสองฝั่ง: "ทีมคว้าฝัน (Catch the Dream)" ตัวหนาเล็ก + แถววงกลม placeholder (ขอบบางไม่มีรูป) 4 วง ใต้แต่ละวงเขียน "[ชื่อสมาชิก]" ตัวเล็กมาก

มู้ด: อบอุ่น มีความหวัง จริงจังแบบมืออาชีพ ไม่ใช่การ์ตูน
```

## Slide 1 — Executive Summary

**Action Title:** "คว้าฝัน" แก้ Dream Gap ด้วย Knowledge Graph + Constraint-Aware Engine ที่ทำได้จริงใน 3 วัน

**ข้อมูล/ตัวเลขที่ต้องปรากฏ:**
- Quote positioning: "Career GPS ของเด็กไทย"
- **5 โจทย์** (ขยายจาก 4 เป็น 5 คู่ ตาม PRD §2): Dream Gap เด็กฝันแคบ (47–50%, OECD) / นักเรียนไม่รู้จะเรียนอะไร (59–60%, survey) / ชั่วโมงแนะแนวน้อย (10–15 ชม./ปี, UNICEF) / ภาระงานครู (42%, สสค.) / ที่นั่งมหาวิทยาลัย > ผู้สมัคร (The MATTER)
- **5 ทางแก้ตรงกัน 1:1**: Discovery+Job Recommendation / Constraint-Aware Screening / ทำงานในคาบเรียน ไม่ใช่ภาระเพิ่ม / Teacher Dashboard อัตโนมัติ / Opportunity Pipeline ให้มหาวิทยาลัย
- Cut-off บรรทัดเดียว: "เราไม่จ่ายเงินให้เด็ก ไม่จัดค่ายเองทั้งหมด ไม่ทำวิดีโอเองทั้งหมด — เราเป็นชั้นแมตช์ + ระบบนำทาง"

**Layout:** 3 คอลัมน์ (เหมือน True Innovation หน้า Executive Summary) + **เพิ่มแถบ "Cut-off" ด้านล่างเต็มความกว้าง** + **badge "Goal" เหนือกล่อง quote** — รวม 5 คู่โจทย์/ทางแก้แทน 4 คู่เพื่อเพิ่มความหนาแน่น

**Prompt:**
```
[แปะ Style Bible]

สไลด์ Executive Summary หัวข้อ: "'คว้าฝัน' แก้ Dream Gap ด้วย Knowledge Graph + Constraint-Aware Engine ที่ทำได้จริงใน 3 วัน"
Layout 3 คอลัมน์แนวนอน คั่นด้วยลูกศรชี้ขวา 2 ลูกศรระหว่างคอลัมน์ กล่องเรียงเป็นแถวเดียวกันซ้าย-กลาง-ขวาให้ตรงกันทุกแถว:

คอลัมน์ซ้าย (แคบกว่า 2 คอลัมน์ขวา): แถบหัวพื้นส้มเล็กเขียน "คว้าฝัน's Goal" ด้านล่างเป็นกล่องพื้นส้มอ่อนสูง เครื่องหมายคำพูดใหญ่สีขาว "Career GPS ของเด็กไทย" ตัวหนา ใต้คำพูดมีย่อหน้าเล็กสีขาว/ครีม 3 บรรทัด: "เปลี่ยนคาบแนะแนว 1 ชม./สัปดาห์ ให้เด็กค้นพบตัวเอง เรียนสกิลจริง สร้างแผนเฉพาะตัว และแมตช์เข้ากับทุน/ค่าย/อาชีพที่เป็นไปได้จริง โดยครูไม่ต้องทำงานเพิ่ม"

คอลัมน์กลาง: หัวคอลัมน์ "โจทย์สำคัญ" ตัวหนาสีกรมท่า ด้านล่างมีกล่องขอบสีส้ม **5 กล่อง** เรียงแนวตั้ง แต่ละกล่องมีหัวข้อตัวหนา + คำอธิบาย 2 บรรทัด + ตัวเลขเล็กมุมขวาบนของกล่อง:
  กล่อง 1 หัว "Dream Gap" เนื้อหา "เด็กฝันกระจุกแค่ 10 อาชีพเดิม เพราะไม่เห็น Role Model" ตัวเลขมุม "47–50% (OECD PISA)"
  กล่อง 2 หัว "ไม่รู้จะเรียนอะไร" เนื้อหา "นักเรียน ม.ปลาย ตอบไม่ได้ว่าอยากทำอาชีพอะไร" ตัวเลขมุม "59–60% (survey)"
  กล่อง 3 หัว "แนะแนวน้อยเกินไป" เนื้อหา "ชั่วโมงแนะแนวจริงเป็นแค่กิจกรรมขั้นพื้นฐาน" ตัวเลขมุม "10–15 ชม./ปี (UNICEF)"
  กล่อง 4 หัว "ภาระงานครู" เนื้อหา "เวลาส่วนใหญ่หมดไปกับงานเอกสาร ไม่ใช่การสอน" ตัวเลขมุม "42% (สสค.)"
  กล่อง 5 หัว "ที่นั่งเกินผู้สมัคร" เนื้อหา "มหาวิทยาลัยหา Talent ตรงความสนใจไม่เจอ" ตัวเลขมุม "seats > applicants (The MATTER)"

## Slide 6 — Technical Architecture: Knowledge Graph + Constraint-Aware Engine

**Action Title:** Knowledge Graph เดียว + Constraint-Aware Engine ขับเคลื่อนทั้งระบบ แทน RAG/LLM ที่ทุกทีมใช้

**ข้อมูล/ตัวเลขที่ต้องปรากฏ:**
- Node types: Job, Skill, Pathway/Course, Organization, Content
- Edge types: requires_skill, leads_to, offered_by, sponsors, related_to
- หลัก "veto, not vote" — ตัด hard constraint ก่อน แล้วจัดลำดับ soft
- 3 คุณสมบัติ: Deterministic / Trace ได้ / Instant Update (ไม่ต้อง retrain)
- PDPA data flow: Anonymous ID (ชั้นวิเคราะห์) vs Consent (ชั้นรายงาน)
- แรงบันดาลใจสถาปัตยกรรม: งานวิจัย constraint-pruning/knowledge-graph (ระบุชัดว่าเป็นแรงบันดาลใจ ไม่ใช่ code ที่ยืมมา)

**Layout:** Network graph กลางภาพ (เหมือนเดิม) + **กล่อง "ทำไมไม่ใช้ RAG" เปรียบเทียบย่อ** + **แถบ PDPA data-flow ล่าง** + กล่อง 3 คุณสมบัติ (ขยายจากเดิม)

**Prompt:**
```
[แปะ Style Bible]

สไลด์ Technical Architecture หัวข้อ: "Knowledge Graph เดียว + Constraint-Aware Engine ขับเคลื่อนทั้งระบบ แทน RAG/LLM ที่ทุกทีมใช้"
Layout:

กลางภาพ (55% ความสูง): แผนภาพ Network Graph แบบเส้นเชื่อมจุด มีโหนดวงกลม 5 สี เชื่อมกันด้วยเส้น: โหนดสีน้ำเงิน "Job" กลางภาพ เชื่อมเส้น label "requires_skill" ไปโหนดสีเขียว "Skill" เชื่อมเส้น label "offered_by" ไปโหนดสีเหลือง "Pathway/Course" เชื่อมเส้น label "offered_by" ไปโหนดสีม่วง "Organization" เชื่อมเส้น label "tags" จากโหนดสีส้ม "Content" กลับเข้า Job — เส้นประ label "related_to" เชื่อม Job ไปยังโหนด Job อีกจุด (job-to-job recommendation)

ใต้แผนภาพฝั่งซ้าย (45%): กล่องเปรียบเทียบเล็ก 2 คอลัมน์ หัว "ทำไมไม่ใช้ RAG/LLM Agent" คอลัมน์ซ้ายพื้นแดงอ่อน "RAG ทั่วไป: black-box, เสี่ยง hallucination, ต้อง train" คอลัมน์ขวาพื้นเขียวอ่อน "Constraint Engine: deterministic, veto-not-vote, ไม่ต้อง retrain"

ใต้แผนภาพฝั่งขวา (55%): กล่องพื้นกรมท่าเข้ม ตัวอักษรขาว 3 บรรทัด แต่ละบรรทัดมีเครื่องหมายถูก: "✓ Deterministic — ผลซ้ำได้ทุกครั้ง ตรวจสอบย้อนหลังได้" / "✓ Trace ได้ — ทุกคำแนะนำอ้างอิงแหล่งข้อมูลจริงเสมอ" / "✓ Instant Update — เพิ่มข้อมูลใหม่ → แมตช์ได้ทันที ไม่ต้อง retrain เหมือน LLM"

มู้ด: ดูเป็นสถาปัตยกรรมเทคนิคจริงจัง น่าเชื่อถือ ไม่ใช่ buzzword ลอยๆ
