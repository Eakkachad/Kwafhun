# Risk Defense — จุดเสี่ยง / Overclaim และแนวทางแก้

> เอกสารนี้สำคัญที่สุดสำหรับการตอบคำถามกรรมการ ใช้คู่กับ `docs/01-pitch/demo-script.md`
> หลักการ: ปรับ "คำเคลม" ให้เป็นข้อเท็จจริงที่ป้องกันได้เสมอ

---

## Overclaim 1 — "AI ช่วยแก้ปัญหาความยากจนได้ทันที"

- **ปัญหา:** AI เสนอได้แค่ข้อมูล/คอร์ส ไม่ได้แก้ค่าอาหาร ค่าเดินทาง ค่า TCAS หรือเด็กที่ต้องออกจากโรงเรียนช่วยครอบครัว
- **Fix:** ปรับสถานะเป็น **Opportunity Router / Pipeline Connector** — AI แมตช์เด็กเข้าหาทุนที่มีอยู่แล้วแต่เข้าไม่ถึง (กสศ. ทุนเสมอภาค / ทุนนวัตกรรมสายอาชีพชั้นสูง / กยศ. / ทุนมหาวิทยาลัย)

## Overclaim 2 — "ถ่ายทำวิดีโอ Interactive อาชีพจำนวนมากเอง"

- **ปัญหา:** ต้นทุนผลิตสูง อาชีพเปลี่ยนเร็ว ทำไม่ทัน
- **Fix:** ใช้ **Crowdsourced Role Model Network & Creator Curation** — รวบรวมวิดีโอสั้นที่มีอยู่ (TikTok/Shorts/YouTube) จาก Creator, นิสิตทุน กสศ., Alumni แล้วใช้ AI ทำ Content Tagging + ซ้อน Interactive Quiz

## Overclaim 3 — "ลดภาระงานครูลง 70% และครูยินดีใช้ทันที"

- **ปัญหา:** ครู สพฐ. ปฏิเสธซอฟต์แวร์ที่ต้องสมัครบัญชี/กรอกข้อมูล/ทำแบบประเมินเพิ่ม และตัวเลข "70%" ไม่มีระบบเชื่อมโยงรองรับ (เป็นเป้าออกแบบ ไม่ใช่ผลลัพธ์ที่พิสูจน์แล้ว)
- **Fix:** ชู **Zero-Setup Classroom Kit** — ครูไม่สมัคร ไม่กรอกข้อมูลล่วงหน้า แค่เปิดลิงก์หน้าจอ ให้เด็กทำกิจกรรมผ่าน QR Code AI ออก PDF "รายงานความสนใจและจุดแข็งนักเรียน" ให้แนบยื่น สพฐ. ได้ทันที
- **แก้คำเคลม:** ไม่พูดว่า "ลดภาระ 70% แล้วจริง" → พูดว่า "ออกแบบให้ลดงานเอกสารต่อคาบโดยอัตโนมัติ" และวัดผลจริงใน pilot

## Overclaim 6 — "การคัดกรองเด็กที่สนใจจริง" ทำลายความเสมอภาค (Portfolio Paradox)

- **ปัญหา:** ถ้าให้เด็กเรียนคอร์ส/ทำแบบวัดเองที่บ้านเพื่อผ่าน screening จะซ้ำรอย bias ของระบบ Portfolio ที่เราวิพากษ์วิจารณ์ (เอื้อเด็กมีเวลา/ทรัพยากร) — และงานวิจัย Deci & Ryan เตือนว่า "ต้องทำเพื่อผ่านเกณฑ์" สร้างแรงจูงใจภายนอก
- **Fix:** **ย้ายคอร์สคัดกรอง + แบบวัดเข้ามาในคาบเรียน** ให้ทุกคนเรียนเท่ากันในห้อง ครูเป็นผู้ดำเนินการ → ผลลัพธ์คือ "ความสนใจจริง" ที่เกิดจากประสบการณ์เท่าเทียม ไม่ใช่การแข่งขันทรัพยากรที่บ้าน

## Overclaim 4 — "ติดตั้ง Local Server/Box ในโรงเรียนชนบททำได้ง่าย"

- **ปัญหา:** ฮาร์ดแวร์ 7,000 แห่ง มีต้นทุนขนส่ง สูญหาย ขาดคนดูแล
- **Fix:** เปลี่ยนเป็น **PWA + Service Worker Caching** ร่วมกับ AIS 5G Edge และ AIS PLAYBOX (เฉพาะโรงเรียน/ครูที่มี AIS FIBRE subscription อยู่แล้ว — PLAYBOX ไม่ใช่ฮาร์ดแวร์ standalone ใช้ไม่ได้ถ้าไม่มี FIBRE) — ไม่ต้องซื้อฮาร์ดแวร์ใหม่เพิ่มสำหรับโรงเรียนที่มี FIBRE อยู่แล้ว

## Overclaim 5 — "เด็กประถม-ม.ต้น ทำตามแผนออนไลน์ได้เอง"

- **ปัญหา:** ขาด Self-Regulated Learning หากไม่มีคนกระตุ้นจะเลิกทำในไม่กี่วัน
- **Fix:** เพิ่ม **Volunteer Mentor Network** — จับคู่นิสิตนักศึกษา (ทุน กสศ./จิตอาสา) เป็นพี่เลี้ยง 15 นาที/สัปดาห์ ผ่านแชต/LINE

## Risk — AI Hallucination

- **Fix:** เปลี่ยนจากการพึ่ง LLM แบบ RAG มาเป็น **Constraint-Aware Matching Engine**:
  - ตัดตัวเลือก "เป็นไปไม่ได้" ด้วย hard constraint ก่อน (ระดับชั้น/เกณฑ์ทุน/พื้นที่/วิชาพื้นฐาน) → คงเหลือแค่ชุดที่ทำได้จริง
  - ดึงจากชุดข้อมูลที่ทีมป้อน/ได้รับอนุญาตเท่านั้น (หลักสูตร สพฐ., ทุน กสศ., TCAS, AIS LearnDi — เก็บเป็นชุดข้อมูลจริง ไม่ใช่อ้าง API สาธารณะ)
  - **Deterministic:** ผลซ้ำกันทุกครั้ง ตรวจสอบย้อนหลังได้ ทุกคำแนะนำ trace กลับที่มาข้อมูลได้ — ตอบโจทย์ "AI black-box" และ PDPA
  - **Instant Update:** เพิ่มข้อมูลใหม่ → แมตช์ได้ทันที ไม่ต้อง retrain (ต่างจาก LLM)
- **แรงบันดาลใจด้านสถาปัตยกรรม:** ดู `docs/04-research/deepman-integration.md`

## Risk — ข้อมูลลิขสิทธิ์จากวิดีโอ Crowdsourced

- **ปัญหา:** การรวบรวมวิดีโอจาก TikTok/Shorts/YouTube มาซ้อน quiz มีประเด็นลิขสิทธิ์/สิทธิ์เผยแพร่ + ความปลอดภัยคอนเทนต์สำหรับเด็ก
- **Fix:** ใช้เฉพาะวิดีโอที่ (1) Creator อนุญาต/ร่วมมืออย่างเป็นทางการ (2) มีสัญญาอนุญาต (เช่น CC) หรือ (3) ทีม/มหาวิทยาลัยเครือข่ายผลิตเอง; มีระบบคัดกรองคอนเทนต์ + ช่องทางรายงานก่อนเผยแพร่สู่เด็ก

## Risk — ความปลอดภัยของเด็กใน Mentor Network

- **ปัญหา:** การจับคู่ผู้ใหญ่/นิสิตกับเด็กอายุ 10–15 ผ่าน LINE มีความเสี่ยงด้าน child safety เกินกว่า PDPA
- **Fix:** Mentor ต้องผ่าน **Vetting** (ยืนยันตัวตน/ตรวจประวัติ), ใช้ช่องแชตที่ monitor + เก็บ log, มีช่องทางรายงานเหตุการณ์, ทำงานตามนโยบายคุ้มครองเด็กของสถานศึกษา และต้องได้รับ Consent ผู้ปกครองก่อน

## Risk — Gamification กลายเป็น "รางวัล" มากไป ทำลายแรงจูงใจจริง

- **ปัญหา (หลักฐานจริง):** Meta-analysis 128 การทดลอง (Deci, Koestner & Ryan 1999) พบรางวัลจับต้องได้ทำลาย intrinsic motivation (d = −0.28 ถึง −0.40) โดยเฉพาะในเด็ก; Hanus & Fox (2015, 16 สัปดาห์) พบว่า badge+leaderboard มากไปลดแรงจูงใจภายในเพราะ social comparison
- **Fix:** ออกแบบ Gamification แบบ SDT (Self-Determination Theory):
  - Reward ต้องเป็น **"โอกาสจริงที่ต่อยอด"** (ที่นั่งค่าย/บูทแคมป์/ทุน) ไม่ใช่ของรางวัลรายกิจกรรม
  - เน้น **Badge + ความคืบหน้า + คำชมเชิงบวก** (feedback เพิ่ม intrinsic motivation d=+0.33)
  - หลีกเลี่ยง leaderboard แข่งเด่นชัด เปลี่ยนเป็น "ความสำเร็จร่วมของห้อง"
  - เล่าให้กรรมการฟังว่าออกแบบตามหลักฐาน SDT อย่างตั้งใจ → จุดแข็งที่เหนือคู่แข่ง

## Risk — PDPA ข้อมูลเด็กอายุเกิน 10 ปี (มาตรา 20)

- **Fix:** **Two-Tier Data Model** — ชั้นวิเคราะห์ใช้ Anonymous ID/รหัสห้อง ไม่มีตัวตน; ชั้นรายงาน สพฐ. ใช้ตัวตนจริง เฉพาะเมื่อได้รับ **Consent ผู้ปกครอง** ล่วงหน้า (ผ่านโรงเรียน)
- **ข้อสังเกต:** "Zero-Setup" หมายถึงครูไม่ต้องกรอกข้อมูลเอง แต่ **การเก็บ Consent ยังต้องมี** (ผู้ปกครอง/โรงเรียน) — ไม่ควรพูดว่า "ไม่ต้องทำอะไรเลย"

## ตารางสรุปความเสี่ยง (Risk & Vulnerability)

| มิติ | จุดอ่อน | ผลกระทบ | แนวทางแก้ |
|---|---|---|---|
| Technical (35%) | AI hallucination / แนะนำเลื่อนลอย | หักคะแนนความน่าเชื่อถือ | Constraint-Aware Engine: ตัด impossible ก่อน + grounded data + deterministic |
| PDPA | เก็บข้อมูลความฝันเด็กอายุเกิน 10 ปี (มาตรา 20) | เสี่ยงกฎหมายรุนแรง | Two-Tier + Consent ร่วมของเด็ก+ผู้ปกครอง |
| Child Safety | Mentor กับเด็กผ่าน LINE | ความเสี่ยงคุ้มครองเด็ก | Vetting + monitor + report channel |
| Market (20%) | โมเดลรายได้ไม่ชัดเจน ดูเป็น CSR | มองว่าไม่ยั่งยืน | B2B2G: กสศ. + มหาลัย + AIS ESG |
| Equity | Screening เอื้อเด็กมีทรัพยากร | ขัดภารกิจความเสมอภาค | คอร์สคัดกรองในคาบเรียน (ทุกคนเท่ากัน) |

## Checklist ก่อนนำเสนอ

- [ ] ใช้คำว่า "ช่วยแมตช์ทุน" แทน "แก้จน"
- [ ] ไม่เคลม "ลดภาระ 70%" เป็นผลจริง — พูดว่า "เป้าออกแบบให้งานเอกสารอัตโนมัติ"
- [ ] ไม่เคลมตัวเลขมหภาค (Q1 +15–20%, 3.3 ล้านล้าน) ว่าเกิดจากเรา — ระบุเป็น "เป้าหมายระยะยาว/บริบทของปัญหา"
- [ ] อธิบาย engine เป็น "Constraint-Based Screening + Grounded Data" ไม่ใช่อ้าง API สาธารณะ
- [ ] ไม่นำตัวเลข performance ของโปรเจกต์ research อื่นมาอ้างว่าเป็นของเรา (ดู deepman-integration.md ข้อ 3)
- [ ] มีคำตอบ "ทำไมเริ่มเมืองก่อน" + "คุ้มครองเด็ก & Mentor Vetting" พร้อม
- [ ] ทุกครั้งที่อ้างสถิติ ชี้ source ได้ทันที
